A. Resumo da implementação

O professor pode editar requested e corrigir changesRequested. O status de origem é obtido dentro da transação: a edição de uma pendência mantém requested; o reenvio de correções grava updated. Os outros estados são rejeitados antes de qualquer escrita.

Antes

A edição aceitava somente requested. Solicitações devolvidas para correção não tinham caminho de reenvio, a lista não recarregava ao voltar e o upload podia reutilizar nomes de imagens.

Agora

A mesma política controla o botão e a transação. Evento e solicitação existentes são atualizados juntos, o formulário exibe o motivo das correções e a listagem é recarregada após o salvamento.

Fluxo do professor

Editar evento→Restaurar dados e primeira etapa→Validar origem e propriedade na transação→Atualizar os mesmos documentos→Recarregar a lista

As datas continuam fora dos campos editáveis. O novo cadastro mantém o fluxo de criação existente e não herda dados da última edição. Falhas no salvamento não limpam os campos preenchidos.

Limite da entrega: as correções locais não representam liberação para produção. As regras de Firestore e Storage continuam restritivas e não foram publicadas nem afrouxadas. A ativação em ambiente real depende da revisão de autorização descrita abaixo.

Explore a política de status

Simulação da matriz; não acessa Firebase. A operação real também exige autenticação, papel ativo e associação correta dos documentos.

Transação e dados preservados

RequestDatasourceImpl aceita um mapa de transições, mantendo compatibilidade com os parâmetros antigos de status único. O callback lê solicitação, perfil e evento antes das escritas. O reenvio preserva os caminhos events/{eventId} e event_requests/{requestId}, usa uma lista de campos permitidos e sincroniza eventName.

As decisões usam o UID autenticado e o papel users/{uid}.userRole. Metadados como decidedBy não são aceitos como prova de identidade; o datasource grava o responsável real e o horário do servidor. A associação com o evento exibido é conferida novamente na transação.

Imagem: substituição e falha

Uploads da RF22 usam nomes aleatórios gerados com Random.secure(). Sem substituição, a transação mantém a imagem que está no documento persistido, evitando restaurar uma URL antiga do formulário.

Após uma rejeição conhecida da operação, a limpeza da nova imagem só é tentada se uma leitura com Source.server confirmar que ela não está referenciada. Falhas de rede ou resultado ambíguo não provocam exclusão. A imagem anterior nunca é apagada por esse fluxo. A exclusão de compensação aceita somente caminhos novos com prefixo events/rf22-.

E. Pendências e decisões de negócio

Permissões de Firestore e Storage

As regras locais negam operações de eventos e uploads. Permaneceram assim. Não foi validada a configuração publicada nem a política de concessão e alteração de papéis. Há um caminho legado em functions/src/approveMemberRequestAndAddToClass.ts que merece revisão: autenticação isolada não prova autoridade para aprovar vínculos ou atribuir papel de professor.

Antes de liberar o fluxo, é necessário validar a origem confiável dos papéis, a leitura autorizada do próprio perfil, a propriedade dos documentos, os campos imutáveis, as transições e a política de acesso às imagens. Essa dependência não foi resolvida por permissões públicas ou por deploy automático.

Aprovação pela interface

O método de persistência approveRequest() foi protegido contra origens inválidas. O diálogo de confirmação continua apenas fechando a janela, sem chamar a persistência. Sua conexão e a publicação do evento são uma pendência independente do reenvio, preservada fora desta alteração.

Quantidade mínima de participantes

O validador existente exige turma e participantes não vazios. O avanço de etapa foi alinhado a essa validação para evitar permitir um envio que será recusado ao final. Não foi criada nova cardinalidade. Continua pendente confirmar com o responsável pelo requisito se uma graduação sem participantes deveria ser válida.

Validação em ambiente integrado

Não foi identificado Firebase CLI disponível nem Emulator instalado no ambiente consultado. Testes com conflitos reais, regras e Storage continuam pendentes. Não foram realizados testes em produção.

F. Riscos restantes

  • Validações Dart não são uma fronteira de segurança contra clientes modificados. Métodos genéricos legados e chamadas diretas ao Firebase dependem de regras ou backend autorizador.
  • Firestore e Storage não compartilham a mesma transação. Uma queda do aplicativo ou falha incerta pode deixar um novo arquivo sem referência; não há rotina automática de coleta desses objetos.
  • Duas edições simultâneas ainda podem sobrescrever campos; não foi introduzido controle de versão do formulário. A transação revalida o status e a propriedade a cada tentativa.
  • A estratégia antiga de nome de imagem no fluxo de criação foi preservada. A geração exclusiva desta entrega é usada no reenvio RF22.
  • Persistem avisos de análise no restante do projeto e whitespace em alterações anteriores fora dos arquivos trabalhados.

Roteiro manual para o Emulator / dispositivo

As marcações são locais e não são salvas após recarregar a página.

47  Future<Either<Failure, void>> updateGenericRequestWithTransaction({
48    required String collectionId,
49    required GenericRequestUpdateParameters params,
50    GenericRequestStatus? expectedStatus,
51    GenericRequestStatus? newStatus,
52    Map<GenericRequestStatus, GenericRequestStatus>? transitions,
53    required Future<void> Function(
54      Transaction transaction,
55      DocumentSnapshot<Map<String, dynamic>> requestSnapshot,
56    )
57    updateRelatedDocuments,
58    Map<String, dynamic> additionalData = const {},
59  }) async {
60    try {
61      final requestReference = _firestore
62          .collection(collectionId)
63          .doc(params.requestId);
64
65      await _firestore.runTransaction((transaction) async {
66        final requestSnapshot = await transaction.get(requestReference);
67
68        if (!requestSnapshot.exists) {
69          throw StateError('Solicitação não encontrada.');
70        }
71
72        final currentStatus = requestSnapshot.data()?['status'];
73
74        final allowedTransitions =
75            transitions ??
76            {
77              if (expectedStatus != null && newStatus != null)
78                expectedStatus: newStatus,
79            };
80        final source = GenericRequestStatusExtension.fromString(
81          currentStatus is String ? currentStatus : '',
82        );
83        final destination = allowedTransitions[source];
84        if (destination == null) {
85          throw StateError('A solicitação não está no status esperado.');
86        }
87
88        await updateRelatedDocuments(transaction, requestSnapshot);
89
90        transaction.update(requestReference, {
91          ...additionalData,
92          'status': destination.name,
93          'updatedAt': FieldValue.serverTimestamp(),
94        });
95      });
96
97      return const Right(null);
98    } on StateError catch (exception) {
99      return Left(ValidationFailure(exception.message.toString()));
100    } catch (exception) {
101      return ExceptionHandler.handleException(
102        exception: exception,
103        contextMessage: 'updateGenericRequestWithTransaction',
104      );
105    }
106  }

128      return const Left(ValidationFailure('Informe o motivo da decisão.'));
129    }
130    return updateGenericRequestWithTransaction(
131      collectionId: _requestCollectionId,
132      params: params,
133      transitions: {
134        GenericRequestStatus.requested: destination,
135        GenericRequestStatus.updated: destination,

145          );
146        }
147        final request = requestSnapshot.data()!;
148        final eventId = request['eventId'];
149        if (eventId is! String || eventId != params.additionalData['eventId']) {
150          throw StateError('Evento e solicitação não correspondem.');
151        }
152        final event = await transaction.get(
153          _firestore.collection('events').doc(eventId),
154        );

157          throw StateError(

159          );
160        }

164          if (destination == GenericRequestStatus.changesRequested)
165            'changeReason': reason,
166          'decidedBy': userId,
167          'decidedByName':

169          'decidedAt': FieldValue.serverTimestamp(),
170        });
171      },

182  ) async {

185

193        );
194      }
195
196      final eventReference = _firestore.collection('events').doc(event.eventId);
197
198      final eventModel = EventEntityModel.fromEntity(event);
199
200      GenericRequestStatus? persistedStatus;
201      final result = await updateGenericRequestWithTransaction(
202        collectionId: _requestCollectionId,
203        params: GenericRequestUpdateParameters(requestId: requestId),
204        transitions: EventRequestPolicy.editingTransitions,
205        updateRelatedDocuments: (transaction, requestSnapshot) async {
206          final requestData = requestSnapshot.data();
207          final source = GenericRequestStatusExtension.fromString(
208            requestData?['status'] as String? ?? '',
209          );
210          persistedStatus = EventRequestPolicy.editingTransitions[source];
211
212          if (requestData == null ||
213              requestData['requesterId'] != userId ||
214              requestData['eventId'] != event.eventId) {
215            throw StateError(
216              'A solicitação não pertence ao usuário ou ao evento informado.',
217            );
218          }
219

222          );

224              actor.data()?['isActive'] == false) {
225            throw StateError(
226              'Somente professores ativos podem editar seus eventos.',
227            );
228          }
229          final eventSnapshot = await transaction.get(eventReference);
230
231          if (!eventSnapshot.exists) {
232            throw StateError('Evento não encontrado.');
233          }
234
235          final existingEventData = eventSnapshot.data();
236
237          if (existingEventData?['eventCreatorId'] != userId) {
238            throw StateError(
239              'O usuário não possui permissão para editar este evento.',
240            );
241          }
242
243          // Converte os dados do evento para atualização.
244          final eventData = eventModel.toMap();
245          eventData['eventName'] = event.eventName.trim();
246
247          // Preserva a imagem existente caso nenhuma nova seja informada.
248          if (eventData['eventImagePath'] == null) {
249            eventData['eventImagePath'] = existingEventData?['eventImagePath'];
250          }
251
252          final updates = <String, dynamic>{};
253
254          for (final field in EventRequestPolicy.editableFields) {
255            if (eventData.containsKey(field)) {
256              updates[field] = eventData[field];
257            }
258          }
259
260          transaction.update(eventReference, updates);
261          transaction.update(requestSnapshot.reference, {
262            'eventName': event.eventName.trim(),
263          });
264        },
265      );
266      return result.map((_) => persistedStatus!);
267    } catch (exception) {
