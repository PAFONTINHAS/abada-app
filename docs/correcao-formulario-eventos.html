Novo evento começa com o formulário limpo

Correção do reaproveitamento de dados da última edição ao iniciar o cadastro de um evento. Este documento explica a alteração e ajuda a conferir o resultado.

Correção aplicada1 arquivo alterado na correçãoAnálise estática sem problemas no arquivo

O que causava o problema

Os controllers do formulário são registrados nos providers globais e continuam ativos quando a tela é fechada. Ao editar um evento, eles recebem seus dados. Antes da correção, o caminho de criação dentro de _initializeForm() apenas encerrava o carregamento e retornava, sem limpar esses controllers.

Antes

Editar evento → sair → criar evento.

O novo formulário podia exibir campos, produtos, seleções e etapa da sessão anterior. A referência interna ao evento editado também permanecia no controller.

Depois

Abrir formulário → limpar estado → escolher o fluxo.

Um novo cadastro começa vazio, na primeira etapa. Na edição, os dados do evento selecionado são carregados após a limpeza.

A alteração no código

Arquivo: lib/features/events/presentation/pages/event_form_page.dart
Local: início de _initializeForm(), linhas 60–64 no momento da correção.

Foram reutilizados os métodos reset() que já existiam nos quatro controllers. O trecho destacado foi adicionado antes da verificação entre criação e edição.

void _initializeForm() {
  final event = widget.eventToEdit;
  final requestId = widget.requestId;

  // Start each form session without state from a previous event.  context.read<EventFormController>().reset();  context.read<EventProductsController>().reset();  context.read<EventGraduationController>().reset();  context.read<EventFormPhasesController>().reset();
  // Criação de um novo evento.
  if (event == null && requestId == null) {
    setState(() {
      _isInitializing = false;
    });
    return;
  }

  // A validação e o carregamento da edição continuam abaixo.
}

Trecho parcial: a última linha de comentário resume o restante do método para facilitar a leitura.

O que é reiniciado

ControllerEstado limpo
EventFormControllerNome, valor, local, descrição, tipo, imagem, datas, evento original, ID da solicitação, erro e indicador de carregamento.
EventProductsControllerLista de produtos, nome e preço em preenchimento e opção de obrigatoriedade.
EventGraduationControllerTurma e IDs dos participantes selecionados.
EventFormPhasesControllerEtapa atual, que volta à primeira etapa.

A inicialização é chamada no callback após o primeiro frame, já existente na tela. Durante esse processo, o corpo do formulário apresenta o indicador de carregamento.

Como os dois fluxos ficam

Criar evento

Abrir a tela→Limpar os 4 controllers→Exibir cadastro vazio

Editar evento

Abrir a tela→Limpar os 4 controllers→Carregar o evento selecionado

A edição restaura os campos, produtos, turma e participantes do evento informado na rota, começando na primeira etapa.
